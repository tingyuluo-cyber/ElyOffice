# ReimuMark 0.1.21 preview tasks

Date: 2026-11-16

Scope: preview task rendering, source marker targeting, shared history and application save state.

Review findings:

- Task targets come from parsed list items in rendering order. Code fences and literal brackets produce no targets.
- A toggle replaces only the marker's middle byte through the existing editor history. Original task text, indentation, BOM and line endings are preserved.
- Callbacks require the same parsed snapshot, current source text and preview mode. Replaced documents and pending parses reject stale clicks.
- The existing Checkbox component provides the accessible name, checked state, Tab stop and keyboard activation. Plain renderer consumers keep their existing behavior.
- Rendering helpers were extracted to keep every changed Rust file at or below 500 lines.

Validation:

- `cargo test --locked -p ely-documents --features test-support`: 550 unit tests and 31 documentation tests passed.
- `cargo test --locked -p ely-mark --bin ely-mark`: 232 tests passed, using the installed Git and pinned PDF worker.
- `cargo clippy --locked -p ely-documents -p ely-mark --all-targets --features ely-documents/test-support -- -D warnings`: passed.
- Added interaction regressions cover toggling, independent undo steps, nested/quoted/numbered/empty tasks, uppercase markers, Space/Enter activation, shifted offsets, read-only task text and stale callbacks.
- The application regression confirms that preview toggles reach the saved text and modified state while preserving UTF-8 BOM and CRLF.
- The extracted standalone package reached `ready ElyMark` and exited successfully. Its editor matches the release build; its PDF worker matches the pinned installed runtime.
- The installed executable was replaced and restarted. A separate fixture verified checking, unchecking and saving from the actual preview UI, then the original document tab was restored.
